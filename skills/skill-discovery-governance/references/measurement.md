# Skill 发现质量测量

## 请求测试集

每个主要业务类别至少准备若干条真实、去标识化的请求样本，并标注：预期 Skill、可接受的备选 Skill、明确不应调用的相邻 Skill。样本要覆盖常见表达、口语/简称、缺少上下文、跨类别需求和边界案例。不要只用 Skill 描述原句做测试。

## 记录字段

| 字段 | 含义 |
|---|---|
| 请求 ID | 可追踪编号，不保存不必要的个人信息 |
| 用户原始表达 | 保留触发语义；必要时匿名化 |
| 预期 Skill | 测试集标注的主要 Skill |
| 实际调用 Skill | 记录会话中真实加载/调用的 Skill，未调用记为“无” |
| 结果 | 正确、漏用、误用、多余调用、无法判断 |
| 根因 | 描述召回、职责重叠、正文不清、工具不可用或用户请求本就不适用 |
| 修正与复测 | 修改内容、回归样本及结果 |

## 指标口径

- 召回率：实际调用到预期 Skill 的样本数 / 应调用该 Skill 的样本数。
- 精确率：实际调用且确实适用的 Skill 数 / 所有实际调用的 Skill 数。
- 误触发率：不应调用 Skill 却被调用的样本数 / 所有不应调用样本数。
- 单次任务可能适用多个 Skill；先标注可接受组合再计算，不能把合法组合当误用。

样本太少时同时报告分子、分母和样本日期，不用百分比掩盖不确定性。80%/85%/90% 等目标只在测试集定义并积累基线后作为运营目标；它们不是 Codex 的默认能力承诺。

## 周检策略

可按每周抽检约 20%（至少覆盖各类别）开始；技能数量少时检查完整集更有信息量。10 个工作日可作为整改跟踪期，不表示届时自动改完。复查重点是新 Skill、最近漏用/误用 Skill、同一职责簇中的重叠项和第三方更新项。所有修改先做职责核对，再用同一请求集回归；不得为追求分数而把 Skill 描述写得过宽。
